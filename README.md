# Circle

اپ وب فارسی برای مربی‌های بدنسازی:

- **مربی:** داشبورد، ثبت شاگرد با شماره موبایل و کد دعوت، چیدن برنامه هفتگی (با تمپو)، دیدن پرونده و پرسشنامه شاگرد، تمرین‌ها و وزن ثبت‌شده
- **شاگرد:** ورود با شماره موبایل و رمز، پرسشنامه اولیه، دیدن برنامه امروز و هفته، ثبت ست‌ها، ثبت وزن
- **کتابخانه حرکات:** ۸۷۶ حرکت با عکس از [free-exercise-db](https://github.com/yuhonas/free-exercise-db) (مالکیت عمومی؛ استفاده تجاری هم آزاد است)، با نام فارسی (و نام انگلیسی زیر آن) و روش اجرای کاملاً فارسی

| بخش | ابزار |
|---|---|
| ظاهر اپ | React + Vite |
| دیتابیس، ورود، سطح دسترسی | Supabase |
| انتشار | GitHub Pages (یا Vercel) |

---

## راه‌اندازی (حدود ۱۵ دقیقه، همه رایگان)

### ۱. Supabase: دیتابیس

1. در `supabase.com` یک پروژه بسازید (`New project`).
2. `SQL Editor` ← `New query` ← محتوای `supabase/migrations/0001_init.sql` ← `Run`.
3. ویرایشگر را پاک کنید ← محتوای `supabase/migrations/0002_phone_login.sql` ← `Run`.
4. همین کار را با `supabase/migrations/0003_tempo.sql` تکرار کنید (تمپوی حرکات).
5. و همین‌طور `supabase/migrations/0004_intake.sql` (پرسشنامه شاگرد).
6. و `supabase/migrations/0005_admin.sql` (پنل مدیر کل).
7. از دکمه **Connect** بالای صفحه، `Project URL` و کلید `anon` (یا `publishable`) را بردارید.

### ۲. Supabase: ورود با شماره و رمز

- `Authentication` ← `Sign In / Providers` ← **Email**:
  - روشن باشد.
  - **Confirm email را خاموش کنید** و `Save`.
- `Authentication` ← `Sign In / Providers` ← بالای صفحه: `Allow new users to sign up` روشن باشد.

> چرا Confirm email خاموش؟ اپ برای هر شماره یک آدرس ساختگی مثل `09121234567@phone.invalid` می‌سازد که ایمیلی به آن نمی‌رسد. پیامکی هم فرستاده نمی‌شود؛ امنیت با **کد دعوت** است.

### ۳. انتشار روی GitHub Pages

1. ریپو باید **Public** باشد (Pages رایگان برای ریپوی خصوصی کار نمی‌کند).
   - `Settings` ← پایین صفحه ← `Change visibility`.
2. `Settings` ← `Pages` ← در `Source` گزینه **GitHub Actions** را انتخاب کنید.
3. `Settings` ← `Secrets and variables` ← `Actions` ← تب **Variables** ← `New repository variable`:

```ini
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

4. تب `Actions` ← `Deploy to GitHub Pages` ← `Run workflow`.
   - بعد از حدود ۲ دقیقه سایت روی این آدرس است: `https://<username>.github.io/<repo>/`
   - از این به بعد هر تغییری در شاخه `main`، سایت را خودکار به‌روز می‌کند.

> اگر Vercel را ترجیح می‌دهید: پروژه را در Vercel اضافه کنید و همان دو مقدار را در `Environment Variables` بگذارید. فایل `vercel.json` آماده است.

### ۴. وصل کردن آدرس سایت به Supabase

- در Supabase: `Authentication` ← `URL Configuration`:
  - `Site URL`: آدرس سایت (مثلاً `https://ashkanpordelwork.github.io/circle/`)
  - `Redirect URLs`: همان آدرس

### ۵. اولین ورود (مربی)

1. سایت را باز کنید ← «ثبت‌نام (بار اول)» ← شماره موبایل خودتان و یک رمز ← کد دعوت را خالی بگذارید ← «ساخت حساب».
2. صفحه «هنوز به مربی وصل نشده‌ای» می‌آید. طبیعی است.
3. در Supabase ← `SQL Editor` شماره خودتان را مربی کنید:

```sql
insert into public.coach_phones (phone) values ('09121234567');
```

4. صفحه سایت را رفرش کنید؛ پنل «شاگردان» باز می‌شود.
5. خودتان را **مدیر کل** کنید (فقط یک بار؛ بقیه مدیرها و مربی‌ها را بعداً از داخل اپ اضافه می‌کنید):

```sql
insert into public.admin_phones (phone) values ('09121234567');
```

6. رفرش کنید؛ تب «مدیریت» اضافه می‌شود.

### پنل مدیر کل

- **نمای کلی:** تعداد حساب‌ها، مربی‌ها، شاگردها، تمرین‌ها و ثبت‌نام‌های اخیر؛ و مواردی که نیاز به بررسی دارند.
- **مربی‌ها:** افزودن مربی با شماره، بستن و باز کردن دسترسی (اطلاعات می‌ماند)، تغییر نام، انتقال همه شاگردها، حذف نقش مربی.
- **شاگردها:** همه شاگردهای همه مربی‌ها، جستجو، افزودن شاگرد برای هر مربی، ویرایش برنامه، انتقال به مربی دیگر، بازنشانی ورود (رمز فراموش‌شده).
- **همه حساب‌ها:** نقش هر حساب، مربی یا مدیر کردن، حذف حساب.
- **گزارش فعالیت:** ثبت‌نام، ورود، تمرین، برنامه، پرسشنامه، و هر کاری که مدیرها کرده‌اند.

همه این دسترسی‌ها در خود دیتابیس کنترل می‌شود؛ کسی که مدیر نیست حتی با دستکاری اپ هم به آن‌ها نمی‌رسد.

### ۶. افزودن شاگرد

1. «+ شاگرد جدید» ← نام و شماره موبایل شاگرد.
2. یک **کد دعوت** شش‌حرفی ساخته می‌شود و متن آماده دعوت را می‌بینید؛ برای شاگرد بفرستید.
3. شاگرد «ثبت‌نام» می‌کند: شماره خودش، رمز دلخواه، و کد دعوت.
4. از آن به بعد فقط با شماره و رمز وارد می‌شود.

**رمز فراموش‌شده:** مدیر کل در صفحه شاگرد ← «تنظیمات» ← «بازنشانی ورود» را می‌زند و کد دعوت تازه را می‌فرستد. شاگرد با همان شماره از نو ثبت‌نام می‌کند؛ برنامه و سابقه‌اش سر جایش می‌ماند.

## اجرای محلی (برای توسعه)

```bash
npm install
cp .env.example .env.local   # مقادیر Supabase را وارد کنید
npm run dev
```

## تست‌ها

```bash
npm test                 # منطق برنامه و ثبت تمرین
scripts/test-db.sh       # قوانین دسترسی دیتابیس روی یک Postgres موقت (نیاز به Docker)
```

تست دیتابیس بررسی می‌کند که:

- هر مربی فقط شاگردهای خودش را ببیند.
- هر شاگرد فقط برنامه خودش را ببیند و نتواند آن را تغییر دهد.
- کسی که ثبت نشده هیچ داده‌ای نبیند.

## ساختار

```
supabase/migrations/   جدول‌ها، قوانین دسترسی (RLS) و تابع ذخیره برنامه
supabase/tests/        تست قوانین دسترسی
src/lib/               منطق برنامه، کتابخانه حرکات، اتصال Supabase
src/pages/coach/       صفحه‌های مربی
src/pages/student/     صفحه‌های شاگرد
public/exercises.json  کتابخانه حرکات (ساخته‌شده با scripts/build-exercises.mjs)
scripts/exercises-fa.json  نام و روش اجرای فارسی هر حرکت (برای اصلاح ترجمه همین فایل را ویرایش کنید)
```

## نکته‌ها

- **ثبت‌نام:** هر کسی می‌تواند حساب بسازد، اما بدون کد دعوتِ درست برای همان شماره، هیچ داده‌ای نمی‌بیند. مربی را فقط صاحب پروژه از SQL Editor تعیین می‌کند.
- **ورود با گوگل:** کدش هنوز در دیتابیس هست (`coach_emails`)؛ اگر بعداً خواستید، فقط باید دکمه‌اش را برگرداند.
- **نام و توضیح حرکات:** فارسی‌اند و در `scripts/exercises-fa.json` نگه‌داری می‌شوند. بعد از ویرایش آن فایل، `node scripts/build-exercises.mjs` را اجرا کنید تا `public/exercises.json` دوباره ساخته شود. جستجو با فارسی و انگلیسی هر دو کار می‌کند.
- **دسترسی از ایران:** دامنه‌های `vercel.app` و `supabase.co` ممکن است فیلتر باشند. یک دامنه شخصی روی Vercel کمک می‌کند.
- **پلن رایگان Supabase:** پروژه‌ای که یک هفته استفاده نشود متوقف می‌شود و با یک کلیک در داشبورد دوباره روشن می‌شود.
